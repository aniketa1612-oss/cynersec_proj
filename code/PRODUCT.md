# Product

## Register

product

## Platform

web

## Users

Authorized cybersecurity analysts, administrators, and report viewers working in academic labs or explicitly approved assessment scopes.

## Product Purpose

Discover, normalize, prioritize, and report vulnerability findings while enforcing authorization and preserving a complete audit trail. Success means analysts can complete a safe mock workflow end to end and clearly distinguish evidence, calculated risk, and recommended follow-up.

## Brand Personality

Precise, calm, accountable. The product should feel like a trustworthy operations console rather than a theatrical “hacker” interface.

## Anti-references

Avoid student CRUD styling, neon cyberpunk decoration, fake terminal effects, excessive cards, low-contrast gray text, and any visual treatment that could make mock evidence appear real.

## Design Principles

- Authorization state is always visible before actions become available.
- Evidence, rule score, ML score, and recommendations remain distinct and explainable.
- Dense data is scannable without hiding important context.
- Risk color supplements text labels; it never carries meaning alone.
- Safe and mock states use explicit language, not subtle decoration.

## Accessibility & Inclusion

Target WCAG 2.1 AA, keyboard-accessible controls, visible focus, reduced-motion support, and redundant text labels for all severity and status colors.
